# แดชบอร์ดภาพรวมการดูแลรถ

ออกแบบหน้าใหม่เฉพาะ dashboard ไม่เปลี่ยน workflow บันทึกซ่อม/PO/สต็อก/LINE
ยังไม่ Deploy และไม่มี SQL หรือการแก้ข้อมูลจริงจากการปรับหน้าจอนี้
โทนสีใช้ตัวแปร --claude-* ชุดเดียวกับเมนูอื่น ไม่กำหนดธีมสีใหม่แยก
ส่วนที่อยู่แถวเดียวกันบน desktop ยืดความสูงเท่ากันตามเนื้อหาที่สูงกว่า
บนมือถือใช้ความสูงตามเนื้อหา ไม่ล็อกความสูงหรือเพิ่มช่องว่างโดยไม่จำเป็น

## โครงหน้า

- ตัวเลขด้านบน: งานซ่อมค้าง, PO รออนุมัติ, เปลี่ยนถ่ายครบกำหนด, อะไหล่หมด
- งานซ่อม: แสดงสูงสุด 6 ใบ เรียงวันที่เปิดเก่าก่อน พร้อมสถานะและจำนวนวันค้าง
- เปลี่ยนถ่าย: สถานะ 5 กลุ่มและรายการสำคัญ 3 คัน พร้อมโปรแกรม/ไมล์รอบถัดไป
- PO: 3 ใบที่รออนุมัติเก่าที่สุด พร้อมร้านค้า/ทะเบียน ไม่มีแสดงยอดเงิน 0 แทนข้อมูลที่ไม่มี
- รายสัปดาห์: เปิดใหม่ ปิดแล้ว ค้าง และค้างข้ามสัปดาห์ พร้อมรายละเอียดเดิม
- อะไหล่: หมดสต็อกก่อน ตามด้วยรายการใกล้หมด แสดงสูงสุด 4 รายการ
- ทะเบียน/ประกัน: หมดอายุหรือเหลือไม่เกิน 60 วัน สูงสุด 4 รายการ

## ลิงก์

ตัวเลขงานค้างเปิดเมนูซ่อมโดยกรอง “งานที่ยังไม่เสร็จทั้งหมด” ไม่รวมงานเสร็จแล้ว
ปุ่มสถานะซ่อมกรองสถานะนั้น เลขใบงานกรองใบที่เลือกโดยตรง
PO รออนุมัติแสดงข้ามทุกเดือน ไม่ใช้เดือนล่าสุดอัตโนมัติสำหรับลิงก์จาก dashboard
เลข PO เปิดรายการนั้น ปุ่มอะไหล่เปิดตามชื่อ ปุ่มเอกสารรถเปิดตามทะเบียน
ตัวเลข/ทะเบียนในส่วนเปลี่ยนถ่ายใช้การกรองและที่มาข้อมูลตามคู่มือติดตามเดิม
การกรองจาก dashboard ส่งไปใช้หลังโหลดข้อมูลหน้าปลายทางเสร็จ ไม่ใช้ timeout เดาเวลา

## การอ่านและข้อผิดพลาด

ใช้ API read เดิม getRepairs/getPOs/getStock/getFullBuses/getWeeklySummary
ส่วนเปลี่ยนถ่ายใช้ read-only endpoint เดิมจาก Feet และ HR-POS
ไม่มี polling ของ dashboard และไม่มี clock interval ที่สะสมเมื่อสลับหน้า
กดรีเฟรชเพื่ออ่านใหม่ หากอ่านบางชุดไม่ได้ ชุดอื่นยังใช้งานได้
ตัวเลขของชุดที่ล้มเหลวเป็น “—” พร้อมข้อความแจ้ง ไม่แสดง 0 ว่าไม่มีงาน
cache เปลี่ยนถ่ายแชร์ระหว่าง dashboard/เมนูรถไม่เกิน 60 วินาที และปุ่มรีเฟรชข้าม cache
role และสิทธิ์ของเมนูปลายทางยังใช้ระบบเดิม ไม่เพิ่มสิทธิ์จากการกด dashboard

## ทดสอบ Local

เปิด run-local.bat ตามเดิม แล้ว Ctrl+F5 เพื่อโหลด HTML/CSS/JS ใหม่
ทดสอบใช้ข้อมูลจำลองเท่านั้น:

```powershell
node build.js
# เมื่อ NODE_PATH มี Playwright
node tests/oil-dashboard-browser.test.js
node tests/oil-tracking-browser.test.js
```

ครอบคลุม 360/390/430/768px และ desktop การเชื่อมตัวกรองไปทุกเมนู
PO ข้ามเดือน รายการเจาะจง XSS escaping สถานะว่างและกรณีโหลดผิดพลาด
ภาพทดสอบอยู่ใน tmp/oil-dashboard/redesign-desktop.png และ redesign-mobile.png
